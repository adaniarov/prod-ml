## Задание 1. Bash-команды (2 балла)

В файле `hw1/solution.py` необходимо записать bash-команды, решающие предложенные
задачи. Для каждой задачи следует заполнить соответствующую переменную.

Файл содержит пять строковых переменных — по одной на задачу. Каждая переменная
должна содержать ровно одну bash-команду (допускаются конвейеры и перенаправления).

### 1.1. Подсчитать количество файлов в текущей директории (0.4 балла)

В текущей директории находятся объекты файловой системы разных типов.
Необходимо вывести количество обычных файлов (regular files), находящихся
непосредственно в текущей директории.

**Пример**

Объекты в директории:

```
a.txt
b.txt
c.sh
dir1/
dir2/
```

**Результат:**

```
3
```

### 1.2. Найти пять самых больших файлов (0.4 балла)

Необходимо вывести имена пяти файлов наибольшего размера в порядке убывания
размера.

**Пример**

| Файл | Размер |
| ---- | ------ |
| `a`  | 1 KB   |
| `b`  | 20 KB  |
| `c`  | 5 KB   |
| `d`  | 15 KB  |
| `e`  | 7 KB   |
| `f`  | 50 KB  |

**Результат:**

```
f
b
d
e
c
```

### 1.3. Отсортировать строки файла и удалить дубликаты (0.4 балла)

Дан файл `input.txt`. Необходимо создать файл `clean.txt`, содержащий уникальные
строки в алфавитном порядке.

**Пример**

`input.txt`:

```
b
a
a
c
b
```

`clean.txt` (результат):

```
a
b
c
```

### 1.4. Найти строки с ERROR во всех .log файлах (0.4 балла)

В текущей директории находятся файлы с расширением `.log`. Необходимо вывести
все уникальные строки, содержащие `ERROR`, отсортированные в алфавитном порядке.

**Пример**

`log1.log`:

```
INFO ok
ERROR failed
ERROR failed
```

`log2.log`:

```
ERROR crash
```

**Результат:**

```
ERROR crash
ERROR failed
```

### 1.5. Найти все пустые файлы (0.4 балла)

Необходимо вывести список файлов нулевого размера.

**Пример**

| Файл    | Размер |
| ------- | ------ |
| `a.txt` | 0 B    |
| `b.txt` | 3 B    |
| `c.sh`  | 0 B    |

**Результат:**

```
a.txt
c.sh
```

## Задание 2. Управление зависимостями с помощью uv (2 балла)

Необходимо подготовить воспроизводимое окружение разработки для тестового
Python-приложения с использованием [`uv`](https://docs.astral.sh/uv/).

### Требования

1. Инициализируйте uv-проект в директории `hw1`.
2. Изучите файл `app.py` (приведён ниже) и определите необходимые зависимости.
3. Зафиксируйте зависимости с помощью `uv`.
4. Версия Python должна быть **3.12** (укажите её в файле `.python-version`).
5. Добавьте в репозиторий все созданные файлы (`pyproject.toml`, `uv.lock`,
   `.python-version`).

> **Подсказка:** для подключения к PostgreSQL используйте пакет
> `psycopg2-binary` (а не `psycopg2`) — он поставляется в виде precompiled
> wheel и не требует системной библиотеки `libpq` для сборки.

## Задание 3. Контейнеризация приложения с помощью Docker (2 балла)

Создайте `Dockerfile`, позволяющий собрать контейнер с тестовым сервисом.

### Требования

1. Используйте базовый образ `python:3.12-slim-bookworm`. `uv` можно установить командой `pip install uv`.
2. Рабочая директория приложения должна быть `/app`.
3. Все зависимости должны устанавливаться через `uv`, используя файлы, созданные
   на шаге 2.
4. Приложение должно запускаться от пользователя `appuser`.
5. При запуске контейнера автоматически должна выполняться команда:

   ```sh
   uv run python app.py
   ```

### Сборка и `app.py`

Файл `app.py` необходим для сборки образа. Тестирующая система автоматически
добавляет его в контекст сборки Docker вместе с вашими файлами: `Dockerfile`,
`pyproject.toml`, `uv.lock`, `.python-version`.

В `Dockerfile` предусмотрите копирование `app.py` в рабочую директорию:

```dockerfile
COPY app.py .
```

Вы можете использовать файл `hw1/app.py` для локальной отладки — во время работы тестов этот файл в любом случае не будет использован.

## Задание 4. Запуск многоконтейнерного приложения с помощью Docker Compose (2 балла)

Создайте файл `compose.yaml`, описывающий инфраструктуру приложения.

### Сервисы

Необходимо создать три сервиса:

| Сервис  | Описание                                                                  |
| ------- | ------------------------------------------------------------------------- |
| `app`   | Тестовое приложение, использующее образ с шага 3.                         |
| `db`    | База данных PostgreSQL (образ `postgres:15-alpine`).                      |
| `extra` | Сервис-заглушка (например, на базе `alpine` с командой `sleep infinity`). |

### Требования

1. Сервис `app` должен иметь сетевой доступ к `db`.
2. Сервис `extra` **не** должен иметь сетевого доступа к `db`.
3. Приложение должно публиковать порт, указанный в переменной окружения `TEST`.

## Задание 5. Публикация Docker-образа в GitLab Container Registry (2 балла)

Соберите Docker-образ приложения и опубликуйте его в GitLab Container Registry.

### Требования

1. Создайте токен с правами `read_registry` и `write_registry`.
2. Выполните авторизацию: `docker login git.culab.ru:5050`, используя имя токена в качестве
   логина, а значение токена — в качестве пароля.
3. Соберите Docker-образ из шага 3.
4. Присвойте ему тег вида:

   ```
   git.culab.ru:5050/course-projects/production-ml/2026-fall-assignments/<username>/hw1
   ```

5. Загрузите образ в GitLab Container Registry с помощью `docker push`.
